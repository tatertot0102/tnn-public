# Phase D implementation and preview gate

React Router 7 framework mode now builds an actual server bundle and route modules. The Vercel preset is enabled for Vercel builds; local builds use the standard server bundle. Public loaders read only published stories/public profile fields, sanitize credits and profile projections, and render title/H1/description/credits/dates/staff content in HTML. The website reader never uses a service key or forwards a visitor's session into shared public reads. Private CMS/login routes are no-store/noindex and retain authenticated Supabase client behavior and RLS enforcement.

The only shared content cache is the CDN, capped at 300 seconds without stale-while-revalidate extension. Concurrent reads are deduplicated while in flight, not cached for a second TTL. A timing-safe secret-protected POST /api/revalidate validates allowed Supabase table/event names and invalidates the shared Vercel cache tag. Set a server-only TNN_REVALIDATE_SECRET (at least 32 random characters), then configure the approved Supabase webhook Authorization header. Do not configure a webhook or expose its secret without the corresponding deployment/configuration approval. Missing secrets and invalid requests fail closed. No webhook was installed here.

Sources: https://vercel.com/docs/frameworks/frontend/react-router and https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package . Framework packages are pinned consistently at React Router 7.18.5, with Vercel adapter 1.3.7; peer dependencies were checked from the package registry. The legacy recovered SPA remains available in Git and legacy helper files use .cjs after the package moves to ESM.

Current local checks demonstrate server-rendered public H1/content and correct cache headers. Browser/end-to-end, Vercel Git preview, and actual webhook delivery verification remain pending before calling D deployed. No production hosting or DNS change is authorized by this source implementation. The user retains the DNS cutover.
